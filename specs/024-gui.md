# Spec 024: GUI

> **Normative.** This document defines `git-loom-gui`, the window on the integration branch: how it is built and started, and what it shows.

## Executable

`git-loom-gui` is a second executable of the package, built only with the `gui` cargo feature (Slint), from the library `git-loom` is built from. `git-loom` never runs the window itself. Slint 1.19 needs Rust 1.95: the feature does too, while `git-loom` keeps the package's `rust-version`.

```bash
git-loom-gui
```

It opens on the repository of the directory it is started in; one process shows one repository. Its arguments are ignored, the sequence editor's apart (below), and neither `--agent` nor `LOOM_AGENT` has an effect on it.

On Windows a release build is a GUI program, with no console; a debug build keeps one. The processes it starts get no console window of their own, a git command that may open an editor apart.

## CLI

```bash
git-loom gui
```

No arguments or flags. Starts the `git-loom-gui` installed in the directory of `git-loom`, or of the file `git-loom` is a link to, in the current directory and off the terminal's streams, and returns without waiting for the window to close. It needs neither git nor a repository itself: what the window cannot open on is the window's to say (see Start-up). Hidden: listed neither in `git-loom --help` nor by the completion scripts.

| Condition | Exact error |
| --- | --- |
| No `git-loom-gui` beside `git-loom` | `` `git-loom-gui` is not installed beside `git-loom`, in `<directory>`⏎`cargo install git-loom --features gui` installs both, in cargo's directory `` |
| Agent mode (Spec 019) | ``the GUI is interactive and unavailable in agent mode⏎Use `loom status` instead`` |
| The executable does not start | `` Failed to start `<path>`: <reason> `` |

## Sequence editor

The sequence editor of a rebase is the running executable (Spec 004), so `git-loom-gui` for a rebase the window starts. Called that way, it answers as `git-loom` does and opens no window.

## Start-up

| Repository state | Result |
| --- | --- |
| On an integration branch | The window, headed by the branch name |
| An operation is paused: loom's (Spec 014), or a rebase or merge of git's with no loom state | The window, headed as the TUI titles its paused view (Spec 020) |
| Anything `loom status` fails on (Spec 001), or an unreadable loom state (Spec 014) | No window: the error in a dialog with a `Close` button, and `git-loom-gui: <error>` on stderr; exit 1 |
| The dialog cannot be created either | `git-loom-gui: <error>` on stderr alone; exit 1 |

The window is titled `<directory of the working tree> — git-loom`.

## Window

A bar holding the heading, above the board. Nothing is under the bar while an operation is paused. Light or dark as the system is.

## Board

What `loom status` lists of the integration branch (Spec 001), top down in the same order. The pointer only opens and closes things on it; a chevron is tinted while the pointer is on it, and nothing else follows the pointer.

- The **trunk** is the integration line: from a ring at its tip, named by the integration branch, to a dot at the base, named by the upstream.
- The base also reads the commit the integration branch stands on (hash and subject), and `<n> new commit(s)` when the upstream has some.
- The trunk has a dot for each commit no branch owns, beside its **card**, and one for each stack owning a commit, beside the first name of the stack.
- A branch is a **frame**: its name as a **tag**, with its remote indicator (Spec 001) drawn as a check mark, an arrow or a cross, and `<n> commit(s)` or `no commits`, then its commits as cards, newest first. A **thread** runs down the frame, from a ring at the tag through a dot at each card, in the color of the branch: one of six, by its rank among the branches.
- No line runs from a frame to the trunk.
- A **stack** is the frames of its branches joined into one, on one thread, the upper branch first. Branches at the same commit share a frame, their tags one under the other.
- A frame closes onto its tag, and opens again, by the chevron of the tag or a double click on it. Closed, it shows none of its commits; its stack keeps its dot on the trunk. Each branch of a stack closes on its own; branches at the same commit close together. A branch owning no commit has no chevron. Every frame is open when the window starts.
- A card is one line: short ID, subject, `<n> file(s)`. It opens in place onto the files of its commit, and closes again, by its chevron or a double click on that line: one line each, the status letter then the path, relative to the directory the window was started in (Spec 001). Several can be open at once, and one stays open while its branch is closed. A commit changing no file has no chevron.
- A frame is as wide as the pane leaves it, between 280 and 560 px; a card on the trunk and the names at its two ends are as wide. The board scrolls when the pane is smaller than it.
- Neither the local changes, nor the context commits before the base, nor a branch `loom status` hides are on it.
