# Spec 024: GUI

> **Normative.** This document defines `git-loom-gui`, the window on the integration branch: how it is built and started, and what it shows.

## Executable

`git-loom-gui` is a second executable of the package, built only with the `gui` cargo feature (Slint), from the library `git-loom` is built from. `git-loom` never runs the window itself. Slint 1.19 needs Rust 1.95: the feature does too, while `git-loom` keeps the package's `rust-version`.

```bash
git-loom-gui
```

It opens on the repository of the directory it is started in; one process shows one repository. Its arguments are ignored, the sequence editor's apart (below), and neither `--agent` nor `LOOM_AGENT` has an effect on it.

On Windows a release build is a GUI program, with no console; a debug build keeps one. The processes it starts get no console window of their own, a git command that may open an editor apart.

## CLI

```bash
git-loom gui
```

No arguments or flags. Starts the `git-loom-gui` installed in the directory of `git-loom`, or of the file `git-loom` is a link to, in the current directory and off the terminal's streams, and returns without waiting for the window to close. It needs neither git nor a repository itself: what the window cannot open on is the window's to say (see Start-up). Hidden: listed neither in `git-loom --help` nor by the completion scripts.

| Condition | Exact error |
| --- | --- |
| No `git-loom-gui` beside `git-loom` | `` `git-loom-gui` is not installed beside `git-loom`, in `<directory>`⏎`cargo install git-loom --features gui` installs both, in cargo's directory `` |
| Agent mode (Spec 019) | ``the GUI is interactive and unavailable in agent mode⏎Use `loom status` instead`` |
| The executable does not start | `` Failed to start `<path>`: <reason> `` |

## Sequence editor

The sequence editor of a rebase is the running executable (Spec 004), so `git-loom-gui` for a rebase the window starts. Called that way, it answers as `git-loom` does and opens no window.

## Start-up

| Repository state | Result |
| --- | --- |
| On an integration branch | The window, headed by the branch name |
| An operation is paused: loom's (Spec 014), or a rebase or merge of git's with no loom state | The window, headed as the TUI titles its paused view (Spec 020) |
| Anything `loom status` fails on (Spec 001), or an unreadable loom state (Spec 014) | No window: the error in a dialog with a `Close` button, and `git-loom-gui: <error>` on stderr; exit 1 |
| The dialog cannot be created either | `git-loom-gui: <error>` on stderr alone; exit 1 |

The window is titled `<directory of the working tree> — git-loom`.

## Window

A bar holding the heading and `Merge a branch…`, above three panes, left to right: the local changes, the board and the inspector, and a status bar under them. Light or dark as the system is; at least 882 by 360 px.

- The panes are parted by one-pixel dividers, each dragged from 3 px either side of it.
- The local changes pane is 260 px wide at first, never less, and never so wide that the board and the inspector cannot have their narrowest.
- The board has 46% of the room right of the local changes at first, between 10% and 90% as the divider between them is dragged, never less than 340 px; the inspector never less than 280 px.
- While an operation is paused no local change is listed and nothing is on the board, so nothing is selected, and the inspector says nothing.
- The window reads the repository when it opens and after each command it runs (Commands); never otherwise. A pause it finds stays shown until the window is started again.

## Local changes

What `loom status` lists of the local changes, in the same order (Spec 001).

- The pane is headed `Local changes`, with `<n> file(s)`, or `no changes`. The header stands for all of them, as `zz` does.
- The list is always open: `→` and `←` on the header do nothing.
- A file is one line: its status letters, the index's in green then the working tree's in red, or `!!` for a conflict and an asterisk for an untracked file; then its path, relative to the directory the window was started in. A conflict is red and bold.
- The list scrolls when the pane is too short for it.

## Board

What `loom status` lists of the integration branch (Spec 001), top down in the same order.

- The **trunk** is the integration line: from a ring at its tip, named by the integration branch, to a dot at the base, named by the upstream.
- The base also reads the commit the integration branch stands on (hash and subject), and `<n> new commit(s)` when the upstream has some.
- The trunk has a dot for each commit no branch owns, beside its **card**, and one for each stack owning a commit, beside the first name of the stack.
- A branch is a **frame**: its name as a **tag**, with its remote indicator (Spec 001) drawn as a check mark, an arrow or a cross, and `<n> commit(s)` or `no commits`, then its commits as cards, newest first. A **thread** runs down the frame, from a ring at the tag through a dot at each card, in the color of the branch: one of six, by its rank among the branches.
- No line runs from a frame to the trunk.
- A **stack** is the frames of its branches joined into one, on one thread, the upper branch first. Branches at the same commit share a frame, their tags one under the other.
- A frame closes onto its tag, and opens again, by the chevron of the tag or a double click on it. Closed, it shows none of its commits; its stack keeps its dot on the trunk. Each branch of a stack closes on its own; branches at the same commit close together. A branch owning no commit has no chevron. Every frame is open when the window starts.
- A card is one line: short ID, subject, `<n> file(s)`. It opens in place onto the files of its commit, and closes again, by its chevron or a double click on that line: one line each, the status letter then the path, relative to the directory the window was started in (Spec 001). Several can be open at once, and one stays open while its branch is closed. A commit changing no file has no chevron.
- A frame is as wide as the pane leaves it, between 280 and 560 px; a card on the trunk and the names at its two ends are as wide. The board scrolls when the pane is smaller than it.
- Neither the context commits before the base nor a branch `loom status` hides are on it.

## Selection

The header and the files of the local changes, and the tags, cards, files of open cards and the base of the board can be selected, all called pieces here; the tip cannot. A selection holds one class of thing (Spec 020): the header is one, the local files another. The base is of no class: it is selected alone.

The **cursor** is the piece the selection was last put on: by a click, a `Ctrl` click that adds, or an arrow key. When it is hidden, the cursor goes to the nearest piece above it.

| Input | Effect |
| --- | --- |
| Click | Selects that piece alone |
| `Ctrl` click, with `Shift` or not | Adds the piece to the selection, or takes it out; a piece of another class than the selection's is left out |
| `Shift` click | Selects from the cursor to this piece, those of the cursor's class, and the cursor stays where it is; with no cursor, or from the base, it is a click |
| `↓` / `↑` | Selects alone the next / previous piece, in the order of `loom status`, from the cursor; with no cursor, the first / last; at either end, the cursor |
| `→` / `←` | Opens / closes the cursor; `←` on a file selects its commit, or the header of the local changes |
| `Esc` | Selects nothing; the cursor stays where it is |

- A click on the tip or on bare board changes nothing.
- A selected card has an accent border; any other selected piece is tinted.
- The pointer marks what it is on and a click acts on: a chevron and any piece but a card are tinted, the border of a card stands out. Nothing appears for the pointer being somewhere.
- A click on a chevron does not select. A double click selects, as its first click does.
- What is closed takes the pieces it hides out of the selection.
- After a key, the pane of the cursor scrolls as far as it takes to show it while it is selected; a piece taller than the board's pane, from its top.
- Nothing is selected when the window starts.

## Inspector

Shows one piece: the cursor while it is selected, else the first selected one in the order of `loom status`. With nothing selected it says `Select a branch, a commit or a file to see its diff.`, wrapped to its width.

| Piece | Title | Diff (Spec 020, Diff Pane) |
| --- | --- | --- |
| Header of the local changes | `Local changes` | `[local changes]` |
| Local file | `<path>`, as its line has it | Working file |
| Tag | `Branch <name>` | Branch name |
| Card | `<short ID>  <subject>` | Commit |
| File | `<path>  in <short ID of its commit>`, the path as its line on the board has it | Commit file |
| Base | `Upstream <label>` | Upstream |

Under the title, a button for each command of the selection's menu that the selection takes (Commands).

The diff is that text, a line colored for what it is (file header, index line, hunk header, added, removed, the commit line of `git show`), each tab as `loom.tuiTabWidth` spaces (Spec 020). The diff of any piece but the base is read the first time it is shown. A diff opens at its first line and column, and scrolls down to its last line and sideways to the end of its longest.

## Commands

A command runs the loom command the TUI runs on the same pieces (Spec 020), made of the selection by the same rules: a selection a command does not take is refused alike. Its prompts are dialogs; the window opens no editor.

| Piece | Menu | Runs |
| --- | --- | --- |
| Header of the local changes | `Absorb` · `Drop all local changes` | `loom absorb` · `loom drop zz` |
| Local files | `Absorb` · `Drop` | `loom absorb <files>` · `loom drop <files>` |
| Card | `Uncommit` · `Drop` | `loom fold <commit> zz` · `loom drop <commit>` |
| File of a card | `Uncommit` | `loom fold <file> zz` |
| Tag | `Push`, `Force push`, `Take the remote version` · `Unmerge` · `Drop` | `loom push <branch>`, `loom push <branch> -f`, `loom update <branch>` · `loom unmerge <branch>` · `loom drop <branch>` |
| Base | `Update` | `loom update` |

- A right click on a piece opens the menu of its class, a line between groups (`·` above), with what the selection does not take greyed out. On a selected piece it is the selection's menu, and the piece becomes the cursor; on any other, the piece is selected alone first. A right click on nothing opens none.
- `Take the remote version` is for a branch with an upstream. `Merge a branch…`, in the bar, runs `loom merge --all`, whose prompt picks the branch.
- While an operation is paused no command applies.
- One command runs at a time. Meanwhile the menus, the buttons and the bar are greyed out, a right click opens no menu, pieces can still be selected, and closing the window is refused, with a notice: it would kill the command's git mid-way.
- A prompt of the command is a dialog over the window, headed by the command line: a question (`Yes`, `Cancel`), a line to type, or a list to pick one item from (`↑`/`↓`, a double click picking and confirming) or to tick at least one of. `Enter` confirms; `Esc` cancels, and so cancels the command.
- When it ends, the window reads the repository again, unless it was cancelled: what was open stays open, but for the cards of commits it rewrote, and a selection goes to the piece the cursor was on, alone, else to the one now in its place, else the nearest above.
- A push refused for a branch that has diverged hints to pick `Force push` in its menu.

## Status bar and log

The status bar says the command running and the step it is at, or what was refused since it started. Once it ends: its last success, with `(and <n> more in the log)` when it reported more, or its last warning, else `Done`; `Cancelled`; or the first line of its error, which a dialog headed by the command line shows whole, unless the log is open. A refused command says why there. Backticks of the CLI's messages are left out.

`Log`, at its end, opens the log over the window: each command run since the window opened, as `$ <command line>`, then each line it reported, a success marked `•`, a warning or an error `!`, the hints under them `›`. `Esc`, `Enter` or a click outside it closes it.

A repository that cannot be read is said in a dialog and the status bar, in place of how a command went, which the log still has; the window shows it as it was.
