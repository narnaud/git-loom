# Spec 020: TUI

## Overview

`git loom tui` opens an interactive, full-screen view of the integration
branch: the branch-aware status tree on the left (the same structure as
`loom status`), and the diff of the item under the cursor on the right.
Rows can be unfolded to reveal the files a commit changed, one or more rows
can be selected, and common loom actions (commit, fold, branch, drop,
reword) run directly from the tree without leaving it: prompts are popups,
results go to a log and the status bar. After every action the tree reloads
to reflect the new state.

## Why a TUI?

The status graph already names every entity with a short ID, but acting on
it still means reading an ID, quitting the pager, and typing a command.
The TUI closes that loop: navigate to the thing you see, press one key, and
the underlying loom command runs with the right arguments filled in.

## CLI

```bash
git-loom tui
```

No arguments or flags. The global `--theme` and `--no-color` options apply.

## Layout

```
┌ Status ──────────────────────┐┌ Diff ─────────────────────────┐
│ ╭─ z0 [local changes]        ││ diff --git a/src/main.rs ...  │
│ │   a1 M  src/main.rs        ││ @@ -1,3 +1,4 @@               │
│ │                            ││ +new line                     │
│ │╭─ b0 [feature-a] ✓         ││ ...                           │
│▓│●▓▓d4f2▓Add▓parser▓(2▓files)││   ← cursor row: shaded bg     │
│ ├╯                           ││                               │
│ ●  9999999 (upstream) ...    ││                               │
└──────────────────────────────┘└───────────────────────────────┘
 Navigate: ↑/↓ | Fold/unfold: ←/→ | Select: space | Commit: c | Fold: f | ...
```

Short IDs are displayed like in `loom status`, so the tree doubles as a
cheat-sheet for manual commands. The cursor row is highlighted with a
subtle background shade (`Theme::selection_bg`: slightly lighter than a
dark background, slightly darker than a light one) so the row's own colors
stay readable — the hunk selector uses the same highlight.

- **Left pane (Status)**: the tree. One row per entity: the
  `[local changes]` header, working files, branch names, commits, commit
  files, the upstream marker, and context commits. Pure graph connectors
  (`│`, `├╯`, ...) are structural rows the cursor skips.
- **Right pane (Diff)**: the diff of the row under the cursor (see
  [Diff Pane](#diff-pane)). Cached per row until the tree reloads.
- **Status bar**: available shortcuts, mode hints, or a transient notice.

## Tree Content and Folding

The tree mirrors `loom status -f`, with folding:

- **Commits are collapsed by default.** A collapsed commit with files shows
  a dim `(N files)` hint. Unfolding reveals one row per changed file, with
  its `<commit-sid>:<index>` short ID.
- **Local changes start expanded**, listing every staged, unstaged, and
  untracked file.
- `→`/`l`/`Enter` unfolds, `←`/`h` folds. Pressing `←` on a child file row
  jumps to its parent and folds it.
- Expansion state is keyed by commit OID, so it survives reloads (a commit
  rewritten by an action gets a new OID and folds again — acceptable).

## Navigation

| Key | Effect |
|-----|--------|
| `↑`/`k`, `↓`/`j` | Move the cursor (skipping structural rows); tree pane |
| `Tab` | Switch focus between tree and diff pane |
| `Ctrl-←` / `Ctrl-→` | Narrow / widen the left pane (2% per press, clamped to 10–90%) |
| `↑`/`k`, `↓`/`j` (diff focused) | Scroll the diff |
| `PgUp`/`PgDn` | Scroll the diff by a page |
| Mouse click / wheel | Focus, move, scroll |
| `L` | Toggle the action log popup (see [Actions](#actions)) |
| `R` / `F5` | Reload the tree from the repo |
| `q` / `Ctrl-C` | Quit |
| `Esc` | Cancel fold, rename, or new-branch mode → clear selection → quit (first that applies) |

## Selection

`Space` toggles selection of the current row and advances the cursor.
Selected rows show a `✓` marker. Selectable rows: the local-changes header,
working files, branch names, commits, and commit files. Actions use the
selection when one exists, otherwise the cursor row. Selection is keyed by
row identity and cleared on reload — losing it after an action is expected.

## Actions

Every action runs the regular loom command on a worker thread while the TUI
stays up (`core::ui`, the TUI counterpart of agent mode: `msg` prompts and
messages are redirected instead of touching the terminal):

- **Prompts** (`msg::confirm/input/select/select_or_input/multi_select`)
  become modal popups: text field, single/multi-select list with `↑/↓`,
  `Space` to toggle, `Tab` to complete a suggestion, `Enter` to confirm,
  `Esc` to cancel. A validator failure re-asks with the reason shown; a
  cancelled prompt ends the command as `Cancelled` (status-bar notice, no
  error popup).
- **Editors** are the one exception: `git::run_git_interactive` (commit
  without `-m`, reword's amend) hands the terminal back to the user for the
  duration and the TUI redraws afterwards.
- **Messages** (`✓`/`!`/`✗` lines, spinners) go to the **log**. Each entry
  starts with the CLI line equivalent to the action, written with the short
  IDs the tree shows (`loom fold a1 fb`), followed by the lines the command
  emitted. `L` toggles the log popup. The status bar animates a spinner with
  the command line while it runs.
- **Success** shows the command's last `✓` line in the status bar until the
  next key. **Failure** opens an error popup dismissed with `Enter`/`Esc`;
  the tree reloads afterwards either way.

While an action runs, tree keys are ignored (only `L` works); `q`/`Ctrl-C`
are keys of the popup while one is open, and of the branch-name field while
a name is being typed. The trace log gets one file per action, named
`loom tui: <command line>`.

| Key | Command | Arguments |
|-----|---------|-----------|
| `c` | `loom commit` | Selected working files; nothing relevant selected → no file args, i.e. the index as-is (already-staged files only, like plain `loom commit`). Branch and message are prompted as usual. Selecting non-working-file rows is an error notice. |
| `f` | `loom fold` | Two-step: `f` captures the selection (or cursor row) as sources and enters fold mode; move the cursor to the target and press `Enter` (or `Esc` to cancel). The target must not be one of the sources. |
| `b` | `loom branch new` | The tree is rebuilt with the branch faked in at its future tip — the cursor commit or branch tip (passed as `-t`), else the base — so it is drawn where it will land (split ownership, stack, co-located group, or empty section), with its name as a text field on its row. In a co-located group the placeholder sits on top, since its name — which decides the final order — is not known yet. `Enter` creates it; `Esc` or an empty name cancels and the tree reverts. |
| `d` | `loom drop` | Cursor commit, branch, or working file; confirmation prompt as usual. |
| `r` | `loom reword` | Cursor commit: opens the editor. Cursor branch: the name becomes a text field on its own row (`Enter` renames, `Esc` cancels, an empty or unchanged name does nothing), and the rename runs as `loom reword <branch> -m <new-name>`. |

Arguments are passed as full commit hashes, branch names, or loom short IDs
(for files), so they resolve through the same paths as manual commands.

### Conflicts

If an action pauses on conflicts (a `LoomState` exists after it returns),
a popup gives the standard guidance to run `loom continue` or `loom abort`
and dismissing it exits the TUI, repeating the guidance in the terminal —
every other command is blocked while paused, so keeping the TUI open would
be misleading. Starting `loom tui` while an operation is paused is blocked
by the global paused-state check, like other commands.

## Diff Pane

What the right pane shows per row kind:

| Row | Diff |
|-----|------|
| `[local changes]` | `git diff HEAD` (staged + unstaged) |
| Working file | `git diff HEAD -- <path>`; untracked files show their content as added lines (binary and oversized files degrade gracefully) |
| Branch name | `git diff <parent-of-oldest-owned>..<tip>` — everything the branch owns; "no commits of its own" when empty; a branch being named with `b` shows no diff |
| Commit | `git show --stat --patch <oid>` |
| Commit file | `git show --format= <oid> -- <path>` |
| Upstream / context | Informational text / `git show` of the context commit |

Diff text is fetched without color and re-colored by line prefix using the
TUI theme, so it follows `--theme` like the rest of loom.

## Edge Cases

- **Not on an integration branch / no upstream**: fails with the same error
  as `loom status`.
- **Hidden branches** (`loom.hideBranchPattern`) are excluded, and short IDs
  are allocated before hiding, exactly like `loom status`.
- **Action fails**: the error is a popup; after Enter the tree reloads.
- **Terminal safety**: a panic hook restores the terminal before unwinding —
  only for a panic on the TUI thread; a crashing worker is reported as an
  error popup. Mouse capture is always released on exit.
